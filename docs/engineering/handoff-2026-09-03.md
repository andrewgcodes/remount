## Part I. What Remount is

### The one-paragraph version

Remount is a protocol and a single static Go binary (Apache-2.0, `CGO_ENABLED=0`,
pure-Go SQLite via `modernc.org/sqlite`; the stripped Darwin/arm64 build at
`7e61cde` is 16,965,826 bytes with the Agent API and embedded recipes; direct
deps are only `coder/websocket`, `creack/pty`,
`fxamacker/cbor`, `x/sys`, `x/term`, `modernc.org/sqlite`) that gives an AI agent a
computer it can run on from anywhere. The agent's computer is a **workspace**: a
filesystem plus processes that can be snapshotted, moved to another node, put to
sleep, and reattached mid-command without losing a byte of output. The workspace
never holds a credential: the node's **broker** substitutes real secrets at the
network edge and every decision lands in one replayable event log. On top of the
workspace sits the **Agent**: a durable, server-side agent session with a stable
id and URL, a derived status, an inbox ("message it and it wakes"), a transcript
mirrored into the control plane (reading never wakes the machine), approvals,
and terminal/files/diff/preview endpoints, driving any harness that speaks the
Agent Client Protocol (ACP) or, as a labelled fallback, a PTY.

### The three layers it owns

| Layer | What Remount owns there | Property it delivers |
|---|---|---|
| **L6, the agent's computer** | workspace runtime: enforced isolation, portable filesystem state, sessions, code in/out, harness launch | durable, neutral |
| **L7, durable runtime / control plane** | leases, generations, snapshots, sleep/wake, the Agent object, HA, node pools, tenancy, metering | durable, open |
| **L9-agent, policy / identity / audit** | brokered credentials, typed egress, approvals, budgets, principals, canonical replayable log, exports, operator console | enforced, brokered, replayable |

Every competitor has at most two of {open, neutral, enforced, durable, brokered,
replayable}. The finished repository has all six in one binary. The open/paid
line is drawn at hosting: everything in the plan is Apache-2.0 code in this
repository; the paid surface (hosted control plane, SSO federation, long
retention, compliance packs) reuses these primitives and is out of scope except
where marked "hosted-ready".

### Explicitly not built, ever

| Item | Why |
|---|---|
| An agent or harness | competes with the customers; Remount runs harnesses |
| An end-user agent UI (chat, transcript view, mobile app) | developers build it on the Agent API; Remount ships an operator console (Phase 5.2, fleet/audit only) and a reference example (`examples/diy-devin/web`) |
| An ACP agent or harness UI | Remount is an ACP **client** (ADR 0042 decision, recorded in ADR 0043/0045); harness TUIs/web UIs run inside the workspace behind the preview proxy |
| Our own model access / model proxying / subscription-token handling | ADR 0039: API keys are brokered for every provider; subscription logins are harness-managed and workspace-resident, labelled `auth.workspace_resident`, refused under `isolated`/`multi_tenant` |
| Our own compute fleet | pools drive the user's vendor accounts; neutrality is the point |
| CONNECT/MITM credential injection in the broker | contradicts ADR 0007; `/d/<host>` reverse proxy + `NO_PROXY` + connectors cover harnesses |
| Raft / multi-writer control plane | fenced active/passive with a controller epoch (Phase 4.4) covers the SLA |

| Cost-based placement | placement is by labels/capacity; cost is the operator's policy |

### How the system is put together

One process kind, three roles, one frame type:

- `remount server` runs the **control plane**, the **relay** and the artifact
  store. The relay (`internal/relay`) authenticates hellos and forwards frames
  by destination id; it interprets nothing else (ADR 0008). The control plane
  (`internal/control`) is one SQLite file: workspaces, claims, leases,
  generations, timers, bindings, grants, bases, queues, Agents, approvals,
  transcript mirror, and the event log, with every resource change and its
  events committed in one transaction through an outbox (ADR 0050).
- `remount up` runs a **node** (`internal/node`): outbound-only uplink to the
  relay, claims workspaces, materializes them through a `workspace.Backend`
  (`process` or `docker` today), runs sessions (`internal/session`: a sequenced
  output log with disk spill, cursors, exec/pty/port runners), snapshots to
  content-addressed `art_sha256:` tar.gz artifacts (`internal/artifact`), runs
  the egress **broker** (`internal/broker`) that rewrites placeholder
  credentials into real ones at the TLS edge, runs the **ACP client**
  (`internal/acp`, `internal/node/agentrun.go`) that drives a harness inside
  the workspace, and rewrites `.remount/env` on every materialize.
- `remount standalone` is server + node in one process; `remount run` /
  `remount agent create` autostart one on a laptop when nothing is listening
  (ADR 0055).
- Clients (`internal/client`, public `client/` + `api/`, the CLI in
  `cmd/remount`, the HTTP API in `internal/server`) talk to control and, with a
  signed **grant** bound to a workspace generation, directly to the node
  through the relay. The Go SDK reconnects, reattaches from the last cursor,
  buffers orphan chunks, and makes every mutation idempotent.

Wire: CBOR frames over WebSocket (`internal/transport`), or an in-memory
`transport.Pipe` with per-connection fault injection for `internal/sim`. Strict
v1 negotiation plus **named capabilities** at hello (`authz-push`,
`controller-epoch`, `session-cap`, `chunked-artifacts`, `approvals`,
`encrypted-artifacts`; ADR 0040): anything an old peer ignoring it would weaken
is a capability, and `isolated`/`multi_tenant` profiles refuse peers lacking
one; `local` requires none. `spec/PROTOCOL.md` is normative.

### Invariants that must stay true (check every change against them)

From `AGENTS.md`, plus the ones added this session:

- The workspace is trusted with nothing. Secrets, policy and lifecycle live in
  the node or control plane. Credentials never enter workspace files,
  snapshots, transcripts or event payloads; prompt/task text is hashed in
  events; `.remount/env` is rewritten on every materialize and never travels in
  a snapshot; preview proxies strip `Authorization`, the session cookie and
  every `remount.bearer.*` WebSocket subprotocol before forwarding.
- A state change that emits no event is a bug; a resource row and its events
  commit in one SQLite transaction (outbox). Every mutation is idempotent.
- Seq 0 of every session is `info`, `exit` is last; a replay gap is a `gap`
  chunk, never silent, never fatal; incomplete output is never reported
  complete (`evicted`, explicit gaps in the transcript mirror too).
- Input is deduplicated by `iseq`. A grant is bound to a workspace generation
  and refused after a move. Revocation is pushed epochs on renew, fail closed,
  latency ≤ lease/3 (ADR 0051).
- `ws.ready` gates `claimed`. Leases renew at ≤ ⅓ interval, including while
  materializing. Nodes self-fence on rejected renew.
- Every workspace **and Agent** state change passes the central transition
  table (`control/state_machine.go`) and validates actor, predecessor and
  authority. Destructive operations retain and fence the source until the
  checkpoint and next state are durably committed. Cancellation is not
  completion: snapshot producers and sessions are joined before capacity is
  released.
- Nothing returned from under `control.mu` is a live pointer. Hoist guarded
  values before unlocking (`scripts/lint-locks.sh` enforces). Request-triggered
  lifecycle work uses `context.WithoutCancel`.
- Every retained collection has admission, accounting, cleanup and an
  observable rejection signal. A check that cannot run is unavailable, never
  healthy. A backend advertises only capabilities it enforces; host- or
  vendor-gated features fail closed with a named reason.
- Agent-specific: status is derived, never set by the harness; the transcript
  is read from the control-plane mirror and never wakes the workspace; only a
  write (message, approval, `diff?wake=true`, preview) wakes; ACP inbound and
  outbound transcript streams stay distinct; frames are redacted and bounded
  before persistence; children never receive broader bindings, providers,
  policy or security than their parent; a scheduled Agent never launches before
  `policy.start_at`; stable `/a/{id}` URLs carry no capability; the browser
  cookie authenticates the preview proxy only (ADR 0058, 0060) — the JSON form
  of `GET /a/{id}` takes a bearer header, the redirect form needs nothing.
- Relay-specific (ADR 0059): once a newer connection for a peer id has been
  reported connected, no observer learns the older one is gone.
- Node run lifecycle: every wait on the harness process is bounded
  (`harnessExit(cmd, grace)` kills the group and then abandons it with exit
  `-1`); a soft `agent.run.cancel` reaches a recipe install that is still
  running (`agentRun.softCtx`); a failed policy sleep or wake is retried after
  `agentRetryBackoff`, never on the next tick (MISTAKES.md #41).

### Resource bounds already in force

Max 1024 live Agents per tenant; 64 pending approvals per Agent; inbox 64
messages × 256 KiB; 64 retained runs; ACP frame 256 KiB; 32 agent terminals;
transcript report payload 256 KiB; durable transcript mirror 64 MiB per Agent;
transcript page 1000 records; HTTP JSON body 1 MiB; fs write 64 MiB; diff
response 4 MiB; wake/launch timeouts 90 s; install 15 min; launch request 60 s;
cancel 15 s; retry backoff 5 s; report retry 500 ms; node report queue 512
reports / 16 MiB with gaps widened on trim; transcript flush 250 ms / 64 KiB;
finished-run markers TTL 1 h, max 4096. Sessions/timers/artifacts/mutation
records have their own bounds (ADR 0018).

### II.4 Review round 1 and hardening (`30094a4`)

Two independent review sessions (control/node/security; HTTP/CLI/examples/docs)
produced findings that were all fixed with regression tests:

- cookie accepted only on `GET /a/{id}` and the preview proxy; terminal
  WebSocket requires bearer; proxy strips every `remount.bearer.*` subprotocol
  and preserves unrelated ones (ADR 0058);
- `Last-Event-ID` takes precedence over `?from`; standalone `--cors`;
- webhook decoding with `UseNumber`, JSON errors with stable codes, bearer
  variants distinguished;
- child `Security` may not be weaker than the parent's (profile, isolation,
  sibling isolation, enforced egress, brokered secrets, audit, deny-default
  network, rule subset), validated before `wsCreate`; early `approve:auto`
  validation uses the effective security after `SecurityProfileFloor`;
- Agent reconcile runs asynchronously so slow node calls never block the
  control loop; `agentBusy` guard;
- bounded node report queue (512 / 16 MiB) that keeps lifecycle reports, drops
  old transcript reports and widens the gap; gap-only reports flushed before
  `finished`; finished-run markers bounded with TTL;
- ACP shutdown ordering captures trailing frames (`TestAgentRunTrailingFrameReachesTranscript`);
- late higher-sequence reports after a finished run return `CodeConflict`
  without failing the Agent; same-sequence duplicates are ignored;
- scheduled-agent restart test with a persistent node key; offline-node
  no-dispatch assertion; implicit `git push` documented;
- macOS temp-dir symlink canonicalization in the handoff test;
- TypeScript client wake default, Python watch `HTTPError`, docs nits.

Also fixed along the way: an old-order redaction bug (redaction must be
initialized from the original spec before the backend's `Prepare` rewrites
it), a queue/sleep validation regression, `staticcheck` findings, stale
`llms.txt`.

### Phase 2 — Enforced isolation and machines (plan §5; L6 trust, L7 capacity)

Goal: the security profiles have backends that satisfy them; Remount can obtain
machines instead of only running on them.

#### 2.1 gVisor `enforced_gateway` backend: `internal/workspace/gvisor/`
- **One mechanism, prototyped first** (a spike commit with a shell script proving
  the path before any Go): the node creates a network namespace per workspace
  (`internal/netns`, netlink via `x/sys`, no `iptables` exec) with a veth pair; the
  host end carries a link-local /30; runsc runs with `--network=sandbox` attached
  to that netns. nftables in the netns: allow TCP from the sandbox to exactly
  `<host-veth-ip>:<broker-port>`; drop everything else — IPv4, IPv6 (`ip6tables`
  equivalent + `disable_ipv6`), UDP, ICMP, raw sockets, DNS. The broker listens on
  the host veth address over plain TCP, so every ordinary `HTTP_PROXY`/base-URL
  client works unchanged; no Unix sockets, no in-sandbox DNS server (the broker is
  addressed by IP in `.remount/env`; name resolution for upstream hosts happens in
  the broker). The proxy/base-URL split (`/d/<host>` vs CONNECT) stays as today.
- Implements `NetworkController`: `ApplyNetworkPolicy` programs rules from
  `proto.NetworkPolicy` and fails closed (any error → veth deleted, sandbox has no
  network at all); `RevokeNetwork` deletes the veth synchronously.
- `Caps{Isolation: "container", EgressMode: "enforced_gateway", NetworkNamespace:
  true, SiblingIsolation: true, BrokerIdentity: "per_session_capability",
  Snapshots: "fs"}`.
- `enforced_gateway` is advertised **only after** the denial conformance suite
  passes on the real backend: direct IPv4 TCP, IPv6, UDP, DNS to 8.8.8.8, ICMP,
  raw socket, and a CONNECT to an unlisted host all fail *at connect*, not at the
  broker; these seven checks are the E4 suite and run in the isolation lane.
- Register in `buildNode`; `doctor` checks `runsc --version`, cap_net_admin, and
  reports `node.diag_unavailable` otherwise.
- Tests: unit tests for netns/nftables programming against a fake `netlink`;
  **integration lane** `.github/workflows/isolation.yml` (ubuntu runner, installs
  runsc): E4 assertions; conformance suite under `--security isolated`. Future
  ADR 0061.

#### 2.2 Vendors as node provisioners, not workspace backends: `internal/provision/{e2b,fly,modal,ix,ssh}/`
- **Decision (future ADR 0062): there is no `remount shim` and no remote `Backend`.**
  `workspace.Handle` returns a host-side `*fsops.FS` and `Prepare` rewrites a local
  `session.Spec`; sessions run in the node process. A remote VM cannot implement
  those contracts honestly, and inventing a node↔shim protocol duplicates the
  node↔control protocol. Instead, **a vendor VM runs a whole node** — which is
  exactly what the 2026-09-02 cross-vendor evidence already did on Fly, Modal, E2B
  and ix. Vendors are therefore `Provisioner`s consumed by node pools (2.4): boot a
  VM/sandbox from the vendor API with the static `remount` binary, run `remount up
  --enroll TOKEN`, and the node dials the control plane like any other.
- Inside a vendor VM the node uses the **gVisor backend where runsc is available**
  (Modal sandboxes and E2B templates can ship it; Fly Machines and ix are Firecracker
  VMs with a normal kernel, so 2.1 works there too) or the docker/process backend
  otherwise. Caps come from the *backend*, never the vendor: a Fly Machine running
  the process backend advertises `cooperative_proxy`; the same machine running 2.1
  advertises `enforced_gateway`. **One node per VM, one tenant per VM** is the
  multi-tenant rule for vendor pools (`PoolSpec.Tenant`), so vendor VM isolation is
  the tenant boundary and no vendor egress allow-list needs to be trusted or
  programmed. Vendor-level network controls (Modal `cidr_allowlist`, E2B network
  rules) are applied when present as defense in depth, never as the enforcement
  claim.
- Vendor credentials live in the control plane's provisioner config only; never on
  a node, never in a workspace.
- Tests: fake vendor API per provisioner; integration lane
  `.github/workflows/vendors.yml` provisions one node per vendor, runs
  create/exec/snapshot/move/destroy through it (§14 lists the secrets), and
  **skips (not passes)** when a secret is absent.

#### 2.3 Firecracker backend (host-gated): `internal/workspace/firecracker/`
- Requires `/dev/kvm`; `doctor` reports unavailability. One base rootfs + kernel
  shipped as artifacts; workspace disk = CoW overlay; jailer on; tap into the
  node-owned netns from 2.1 (shared `internal/netns` package).
- `Checkpointer` returns `fs+mem` using Firecracker diff snapshots
  (`track_dirty_pages`); restore via uffd lazy paging. `Snapshots: "fs+mem"`,
  `Isolation: "microvm"`, `EgressMode: "enforced_gateway"`.
- Move preserves processes: node emits `ws.moved{processes: "preserved"}`; other
  backends emit `processes: "restarted"` (event field added for all backends).
- Tests: unit with a fake Firecracker API; integration lane on a KVM-capable
  self-hosted runner if available, else documented manual runbook in
  `docs/operations.md`. Future ADR 0063.

#### 2.4 Node pools: `internal/pool/`
- Declarative `PoolSpec{Name, Vendor, Min, Max, Labels, Backend, IdleScaleDown,
  Region, Size}` stored in control; `Reconciler` creates/destroys nodes via a
  `Provisioner` interface per vendor (2.2: `fly`, `modal`, `e2b`, `ix`, `ssh` for BYO
  hosts). `PoolSpec.Tenant` pins a vendor pool to one tenant (one node per VM, one
  tenant per VM). Provisioned nodes run `remount up` with a one-time enrollment token
  (Phase 3.4) — no long-lived node secret in the image.
- Claims that find no eligible node trigger scale-up; nodes idle > `IdleScaleDown`
  with zero workspaces drain and scale down. Placement stays label/capacity based
  (never cost).
- Events `pool.scaled{from, to, reason}`, `pool.provision_failed`. CLI `remount pool
  create|ls|get|rm`. Sim test with a fake provisioner: claim at min 0 scales to 1,
  idle scales to 0, provision failure is retried with backoff and surfaced.
  Future ADR 0064.

#### 2.5 Secrets at rest
- Artifacts encrypted with a per-artifact data key (AES-256-GCM, std lib), wrapped
  by a tenant key version, wrapped by a master key from `REMOUNT_MASTER_KEY` or a
  `KeyProvider` (`env`, `file`, `awskms`, `gcpkms` via hand-written REST).
- **Identity vs storage (future ADR 0065):** the *logical* id stays `art_sha256:<plaintext
  hash>` (ADR 6 holds; moves, `RestoreFrom`, `doctor` unchanged). The *physical*
  object key is `tenants/<tenant>/<keyver>/<id>`, so the same plaintext under two
  tenants (or two key versions) never collides. Consequences, written into the ADR:
  dedupe (4.1) is **per tenant** — cross-tenant dedupe would leak existence of
  content and is refused; key rotation writes a new `<keyver>` on next write and a
  background re-wrap job migrates old objects while both versions stay readable;
  `doctor --deep` verifies plaintext hash after decrypt and reports objects still
  on a retired key version.
- Fuzz test: a snapshot never contains `.remount/env` or any binding placeholder
  value (extend existing invariant test to fuzz the exclude list). Future ADR
  0065.

### Phase 3 — Governance (plan §6; L9-agent)

Goal: the broker and control plane become the enterprise's agent-governance system
of record; a single shared token no longer exists.

#### 3.1 Approve-on-first-use
- `EgressRule.Mode: "allow"|"deny"|"approve"` (default `allow`). **Approval is a
  durable control-plane resource, not a parked connection.** On first match the
  broker creates `Approval{ID, WS, Principal, Host, Method, PathHash, BodyHash,
  ExpiresAt}` via control (idempotent on the request fingerprint), emits
  `egress.pending{id,…}`, and holds the HTTP request only for a short node-local
  window (`ApprovalWait`, default 30 s, bounded `MaxPending`). If undecided by then
  the broker returns `403` with `X-Remount-Approval: <id>` and `Retry-After`; the
  approval stays open until `ApprovalTimeout` (default 10 min) →
  `egress.denied{reason: approval_timeout}`. When approved, the decision is stored
  with a TTL and the **resubmitted** request (same fingerprint, or same host if
  `remember: host`) passes without a second approval. Node or control restart loses
  nothing but the in-flight connection; the agent's own retry completes the flow.
- Decision ops on control: `egress.approve{id, remember: none|host|rule}`,
  `egress.deny{id}`. `remember: host` appends an allow rule for that host to the
  workspace's policy (event `policy.updated`). Decision recorded as
  `egress.allowed{approved_by, decision_id}`. `remount run --approve on-request`
  documents that harness retries are what make approvals seamless.
- CLI `remount approvals ls|approve|deny`, `remount run --approve on-request`.
  Outbound notification via 3.7. Sim test: E6. Future ADR 0066.

#### 3.2 Budgets and rate limits
- `Budget{Window: 1h|1d|30d, MaxRequests, MaxTokens, MaxCostMicros}` attachable to a
  binding, a workspace, a principal, or a tenant; enforced in `broker.proxy` before
  substitution. **Two tiers with different guarantees, stated in the API:**
  `MaxRequests` and `MaxTokens` are **hard** — enforced by reserve-then-settle
  against control's authoritative counter (reserve `max_tokens`/1 request before
  release, settle the parsed `usage` after; a reservation that cannot be made is a
  denial; reservations expire if the node dies). `MaxCostMicros` is **estimated**:
  cost = settled tokens × a checked-in `pricing.json` (per provider/model, marked
  approximate, overridable per tenant); the API field is `MaxEstimatedCostMicros`
  so nobody mistakes it for a billing guarantee. Node-local soft counters exist
  only as a fast-path denial, never as a grant.
- `internal/broker/meter/` parses `usage` from OpenAI/Anthropic/Google/OpenRouter
  response bodies (streaming and non-streaming; unknown providers count requests
  only and say so in `budget.unmetered`).
- `egress.denied{reason: budget_exceeded, budget_id}`; `GET /v1/usage?tenant=&ws=&
  principal=&window=` and `remount usage`. Sim test: E7. Future ADR 0067.

#### 3.3 Response controls (small, optional flag)
- Per-rule `Redact: []string` (RE2 patterns) applied to response bodies before they
  enter the workspace; `egress.redacted{count}`. Default none. Unit tests in
  `broker_test.go`.

#### 3.4 Identity: `internal/identity/`
- Principals: `operator`, `agent`, `node`, `viewer`, `service`; each with
  `Tenant`, `Roles`. Implements `control.Authenticator` and `control.Authorizer`
  (the seams exist). Tokens: Ed25519-signed, short-lived (default 1 h), refreshable;
  revocation list in the event log (`identity.revoked`) and enforced at relay hello
  and at every node call; enrollment tokens for nodes (one-time, 10 min).
- **Per-session broker capabilities (`session-cap`).** Today one capability per
  workspace lives in `.remount/env`, so the broker cannot know which principal's
  process made a request. `Prepare` injects a per-session `REMOUNT_BROKER` whose
  capability encodes `spiffe://<tenant>/ws/<id>/gen/<n>/principal/<p>`; the
  workspace-level `.remount/env` capability remains for the recipe launcher and is
  attributed to the workspace owner. Every `egress.*` and `cred.used` event carries
  `principal`; revoking a principal (0.11) invalidates that principal's session caps
  and closes their sessions while the workspace, its owner's capability and other
  principals continue — that is the precise E8 claim. Bindings gain `Principals`
  enforcement (already in the struct) and `Workspaces []string`.
- Operator login: `remount login` with OIDC device flow against a configured issuer
  (hosted-ready); local mode keeps `--token` but it becomes an `operator` principal.
- CLI `remount principal create|ls|revoke`, `remount token issue --role agent
  --ttl 1h`. Sim test: E8. Existing sim tests migrate from shared token to an
  issued operator token in their own commit. Future ADR 0068.

#### 3.5 External secret sources for bindings
- `Binding.Source string` replaces literal `Secret` for production modes:
  `env://NAME`, `file:///path`, `vault://<addr>/<mount>/<path>#<key>` (token or
  AppRole via REST), `awssm://<arn>` (SigV4 REST), `gcpsm://projects/…/versions/…`,
  `github-app://<app_id>/<installation_id>` (1.5). Resolved at substitution time
  with TTL cache; never written to SQLite; rotation = cache expiry. `bindings.json`
  with literal secrets remains valid only in `standalone`.
- `doctor` verifies each source is reachable without printing values. Future
  ADR 0069.

#### 3.6 Tenancy and metering: `internal/tenant/`
- Every resource carries `Tenant` (fields exist); add enforcement: a `Subject` sees
  only its tenant unless role `operator` on tenant `*`. Per-tenant quotas
  (`MaxWorkspaces, MaxNodes, MaxArtifactBytes, MaxActiveSessions`) enforced at

- Metering counters as events: `usage.workspace_seconds` (per lease renewal),
  `usage.brokered_request`, `usage.bytes_in/out`, `usage.storage_bytes` (hourly
  artifact GC pass). `/v1/usage` aggregates; `remount usage --tenant`.
- Hosted-ready hooks: `BillingExporter` interface with `jsonl` and `stripe_meter`

#### 3.7 Webhooks in, notifications out

### Phase 4 — Continuity at scale (plan §7; L7)

Goal: never lose work; no size, duration, or single-process limit stands between an
agent and a multi-day task.

#### 4.1 Chunked snapshots: `internal/artifact/chunked/`
- Content-defined chunking (FastCDC, 64 KiB avg, 16 KiB–256 KiB bounds) into the
  `BlobStore`; manifest (paths, modes, xattrs, chunk lists) is itself an artifact
  (`art_sha256:` of the canonical manifest) so ADR 6 holds. `Snapshot` uploads only
  chunks `Head` says are missing; `Restore` fetches missing chunks, eager by default,
  `--lazy` prefetches the manifest's hot set (files touched in the last session) and
  backgrounds the rest.
- Client side (1.1 `localfs.Pack`) uses the same chunker so `--dir .` uploads only
  unseen chunks. Full-tar export retained for `doctor --deep` and interop. Lifts the
  8 GiB cap (manifest-bounded). Metrics: `snapshot_bytes_uploaded`,
  `snapshot_dedupe_ratio`. Sim test: E9 with a 500 MB fixture (generated).
  Future ADR 0072.

#### 4.2 Tiered session log
- `internal/session/log.go`: memory → disk → `BlobStore` (sealed 64 MiB segments as
  artifacts referenced from the session record). Reattach from any `seq` streams
  from the right tier; `gap` becomes impossible while storage is available and is
  emitted only when a tier is unavailable (with the tier named). Retention per
  tenant. Sim test: E11 with a fast fake producer. Future ADR 0073.

#### 4.3 S3-compatible blob store: `internal/artifact/s3/`
- `BlobStore` over S3 REST with hand-written SigV4 (no SDK), path- and
  virtual-host-style, works with MinIO/R2/GCS-interop. Streaming multipart for
  >64 MiB. Integration lane with MinIO in CI. Config `--blob s3://bucket/prefix`.

#### 4.4 Control-plane durability and failover (warm standby with a stated RPO)
- **Decision (future ADR 0074): warm standby, non-zero RPO, honestly measured; not Raft,
  not synchronous replication.** Continuous SQLite WAL shipping to the `BlobStore`
  (`internal/control/replicate/`, Litestream-style, 1 s ship interval + periodic
  full snapshots, epoch-tagged). **RPO ≤ ship interval (1 s default), RTO ≤ 5 s** are
  the numbers the runbook promises and the sim measures; a deployment that needs
  RPO 0 runs a single controller on durable block storage with fast restart (already
  tested) — the docs say which to pick.
- Fencing: `remount server --standby` polls a lease object (conditional PUT,
  `If-Match`); on expiry it promotes and bumps the **controller epoch**
  (`controller-epoch` capability) carried in every event, grant and renewal. Nodes
  reject a lower epoch (`renewal rejected: stale controller epoch`, node keeps its
  leases, no fence); the blob store rejects it via epoch in object names. Under a
  partition where the old controller is alive but cannot reach the store, it stops
  issuing decisions when its own lease age > lease TTL (self-fence) — the same rule
  nodes already follow.
- **Recovering the lost tail.** The promoted controller may be missing up to RPO of
  commits. It does not pretend otherwise: it enters `reconciling` and asks every node
  for its authoritative view (workspace ids, generations, lease state, last
  snapshot, open sessions — nodes already hold this for re-adoption). Any resource
  whose node view is ahead of the store is repaired from the node and the repair is
  an event `control.reconciled{ws, from_epoch, field}`; a generation the store never
  saw is adopted, never re-issued, so no duplicate generation. Mutations in the
  lost window whose effects live only in the store (a binding update, a pending
  approval) are lost and listed in `control.recovered{lost_window_ms, epoch}` so an
  operator can replay from client idempotency logs.
- E10 is therefore worded: standby promotes ≤ 5 s; the in-flight move completes or
  is rolled back; no duplicate generation; event log has **no silent gap** — the
  lost window, if any, is itself an event. Sim: kill CP mid-move with the store
  ship delayed, assert all four. Runbook in `docs/operations.md`.

#### 4.6 Shared data volumes (small, explicit scope)

  --from SEQ --follow`. Cursor persistence in control (`export.cursor`). Test: E16
  against an in-process collector. Future ADR 0076.

#### 5.2 Console: `web/` embedded in the binary
- **Decision:** Vite + Preact + TypeScript, no component library, hand-written CSS,
  `xterm.js` for the terminal (the one unavoidable dependency). Served at `/console`
  from `embed.FS`; built in CI (`make web`), committed `dist/` checksum verified so
  the binary stays reproducible; hard cap 1.5 MB gzipped enforced by CI.
- Views: fleet (nodes, pools, workspaces by state), workspace (sessions, snapshots,
  generation history), **live terminal** (WebSocket attach endpoint added to
  `internal/server`, reusing `client.Attach` replay so scrubbing back is free),
  timeline over `/v1/events` with filters (principal, session, credential),
  credential-use and `leak_blocked` view, pending approvals with approve/deny,
  usage/budgets, quarantine. Read-only by default; mutating actions require
  `operator` role (3.4).
- Playwright tests in CI for E15 against a sim-backed server. Future ADR 0077.

#### 5.3 SDKs: `sdk/python`, `sdk/typescript`, generated from `proto/types.go`
- `cmd/protogen`: walks `internal/proto/types.go` (AST, not reflection) → JSON
  Schema + op table (`spec/protocol.schema.json`, committed) → generated body types
  for both SDKs. CI fails if generated output differs from committed.
- Hand-written transport in each SDK mirroring `internal/client`: WebSocket + CBOR
  frames, request correlation, reconnect with backoff, reattach with `from` seq,
  orphan-chunk buffering, idempotency keys on every mutating call, artifact upload.
  Python: `httpx`, `websockets`, `cbor2`, asyncio; TypeScript: `ws`/WebSocket,
  `cbor-x`, ESM + CJS. Publish targets `remount` (PyPI) and `@remount/sdk` (npm).
  **Decision:** both ship in this plan; Python is implemented first (it is where
  OpenHands, LangGraph, Pydantic AI, CrewAI and most research harnesses live),
  TypeScript immediately after (Mastra, Vercel AI SDK, opencode plugins); the

- `integration/sdks/`: E12 scripted in both languages against the same server.
  Future ADR 0078.

#### 5.4 MCP: `remount mcp serve` and `remount mcp wrap`

  harness reads.
- `wrap <server cmd>`: runs an MCP server with its env rewritten to placeholders and

  credentials for free.
- Test: E13 scripted with headless runs of two harnesses in CI when their keys are
  present (skip otherwise); unit tests with the MCP SDK's in-memory transport.

## Part IV. How to work

### IV.1 Rules (from `AGENTS.md` and the plan §0; all still binding)

1. Read `AGENTS.md`, `docs/engineering/README.md` and its current-status link,
   the relevant ADRs, `MISTAKES.md`, `docs/engineering/hardening-lessons.md`,
   and `.agents/skills/remount-hardening-review/` before changing a moving
   checkout. Record `git status --short --branch`, `HEAD` and `origin/main`
   first; treat unfamiliar dirty paths as someone else's.
2. Phases are dependency-ordered; gate after every phase:
   `make lint && make race && make build && make conformance && make public-api`,
   plus `make fuzz FUZZTIME=30s` after touching `proto`, `artifact`, `broker`,
   `fsops`. Also run `go run ./cmd/acpgen -check`, `staticcheck ./...`,
   `govulncheck ./...` (binaries live in `$(go env GOPATH)/bin`), and
   `make docs` whenever docs change (`llms.txt` freshness is part of `make
   lint`). A red `make race` means not done.
3. One commit per numbered item, Conventional Commit style
   (`feat(scope): ...`, `fix(...)`, `test(...)`, `docs(...)`); the repository
   commit wrapper requires `-m`. Never amend, never `git add .`, never skip
   hooks, never force-push main, never `reset --hard`/`clean -fd`.
4. Every new behavior has a test; two peers involved → `internal/sim`
   (`newWorld`, `w.node`, `w.client`, `mustWS`, `w.cut` is the fault
   injector; reconnect tests assert byte-identical output). Backend isolation →
   an integration lane in `.github/workflows/`, never pretend sim covers it.
5. Every design decision is a new ADR (never edit an existing one); every new
   op/event/field lands in `spec/PROTOCOL.md` the same commit (§6 control ops,
   §7 node ops, §11 events, §6.3 HTTP). Protocol changes need negotiation,
   compatibility and golden coverage; security-relevant changes are named
   capabilities, not additive fields.
6. Dependencies: allowed additions are `github.com/modelcontextprotocol/go-sdk`
   (MCP) and `golang.org/x/crypto` only if std `crypto` is insufficient. No
   AWS/GCP SDKs: S3 is hand-written SigV4 over `net/http`. Anything else: stop
   and ask. Prefer versions published ≥ 7 days ago.
7. Honesty: backends advertise only what they enforce; `doctor` never renders
   an unrun check as a pass; gated features fail closed with a named reason.
8. Never modify a test to make it pass; fix a wrong test in its own commit with
   reasoning.
9. Secrets: never printed, logged, written to a workspace, or committed; vendor
   tests read from CI secrets and skip (not pass) when absent.
10. Split when touched: before an item that changes `control.go`, `node.go` or
    `main.go`, move only the code it touches into its own file in a pure-move
    commit, then change it. New code goes in new files.
11. Style: comments say why; every exported identifier has a doc comment; wire
    errors use `proto.Err(code, ...)` with stable codes (`CodeBadRequest` is
    the validation code; there is no `CodeInvalid`); new metrics are named vars
    in `internal/metrics` incremented at the site; CLI subcommands parse via
    `parse(fs, args, n)`, never `fs.Parse`.
12. Before a lifecycle edit, state: authority, resource, irreversible action,
    durable commit point, observable postcondition; add a regression test that
    makes the forbidden outcome observable.

  incompatible assumptions surface before code does.
- **Ownership by package, not by feature.** Items that are leaf packages
  parallelize cleanly: 2.5 (`internal/artifact` encryption + `KeyProvider`),
  4.1 (`internal/artifact/chunked`), 4.3 (`internal/artifact/s3`), 4.2
  (`internal/session` tiers), 3.2 meter (`internal/broker/meter`), 3.3
  redaction (`internal/broker`), 5.1 exporters (`internal/eventlog` +
  `cmd/remount`), 5.3 (`cmd/protogen`, `sdk/`), 5.4 (`cmd/remount mcp`,
  client-only), 5.2 (`web/`), 2.1 (`internal/workspace/gvisor`,
  `internal/netns`; needs a VM with runsc), 2.3 (`internal/workspace/firecracker`;
  needs KVM). Items that rewrite `control.go`'s state or the relay/transport
  (3.4 identity, 3.6 tenancy, 4.4 failover, 2.4 pools' claim hook) are
  integrator-owned and sequential; children may prepare pure-move splits and
  interfaces for them but not land behavior.
- **Interface contracts first.** Where a leaf item needs a hook in a shared
  file (e.g. 2.4 needs "claim found no eligible node" from control; 3.2 needs
  a reserve/settle op), the integrator lands the hook and its test in one small
  commit before the child starts, so the child never edits shared files.
- **One branch per child, PR into main, integrator merges in dependency
  order**, running the full gate on each merge and again on the final tree.
  Children rebase on main before their PR; conflicts in shared files are the
  integrator's to resolve.
- **Gather one child at a time with short timeouts**; never one blocking call
  for many sessions. Ask each child to report: commits, gate output, what was
  skipped and why, open questions.
- **Review round after each phase**: two independent reviewers with disjoint
  scopes (control/node/security vs. API/CLI/examples/docs), fix confirmed
  findings with regression tests, repeat until neither reports an actionable
  finding. That loop found the cookie scope hole, the child security ceiling
  and the report-queue bounds this session; it pays for itself.

### IV.4 Pitfalls that cost time this session (add to MISTAKES.md as you hit more)

- `context.WithoutCancel` for anything a request handler kicks off; the
  webhook handler once cancelled its own event append at 202.
- Never hold `control.mu` across a node call; Agent reconcile had to become
  asynchronous with a busy-set guard.
- Every bounded queue needs a "what was dropped" signal; the report queue's
  trim once lost a gap when the run ended right after it.
- Initialize redaction from the original spec before `Backend.Prepare`
  rewrites env; otherwise the canary test is the only thing that catches it.
- Restarting an SQLite-backed node in a test needs the same node key, and a
  restarted node starts in `claiming`: re-adopt explicitly.
- macOS canonicalizes `/var/folders` to `/private/var/folders`; compare
  `filepath.EvalSymlinks` results.
- Browser `EventSource` cannot set `Authorization`; use the transcript
  WebSocket with the `remount.bearer.<base64url>` subprotocol.
- `ListAgents` returns `[]proto.Agent`; `c.WriteFile` returns one value;
  `proto.MustMarshalJSON` and `proto.CodeOf` do not exist (use `encoding/json`
  and match on `*proto.Error`).
- `agent.run.started` is emitted twice per run (pending, then active).
- `leak_blocked` is a broker audit decision, not an event type
  (`egress.denied` is).
- A platform-only CI failure is a scheduling-order bug until proven otherwise
  (MISTAKES.md #40); reproduce by holding one side open in a unit test rather
  than by looping the sim test.
- `grep | head` exits 0; prove leak scans with a planted canary.
- `gofmt` realigns const blocks; assert a scripted edit's postcondition.
- Generated docs (`llms.txt`, `llms-full.txt`) are checked by `make lint`;
  run `make docs` after any docs change.
- The memory journal repo (`andrewgcodes/devin-gao-memory-journal`,
  `remount/2026-09-03-build-session-phase0-phase1.md`) holds the narrative of
  this session; its main moves, rebase before pushing.
