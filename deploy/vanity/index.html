A durable computer for AI agents.

Remount gives an agent a workspace it can keep: a filesystem and the processes in it, on a machine you control. Snapshot it, move it to a GPU box, put it to sleep, reattach to a command that is still running, and call APIs with keys the workspace never sees. One static Go binary, one wire protocol, self-hosted, Apache-2.0.

What you can do with it

reattach, never lose output

Run a coding agent for hours. Close the laptop, reopen it, attach, and read what you missed. The session lives on the node, not in your terminal, and a dropped range is an explicit gap.

move a workspace mid-task

Start on your laptop and ws move to a GPU box. The filesystem is snapshotted and restored; files and policy follow, and a stale client cannot act on the old placement.

keys the agent never sees

The workspace holds a placeholder. The node's broker substitutes the real key only for the hosts that binding allows, records every use, and a revocation reaches a live workspace within one renewal.

background work with a deadline

A lease keeps a workspace awake until a deadline stored in the control plane. It survives your own service crashing, then sleeps the workspace instead of billing you forever.

a browser inside the workspace

Navigate, screenshot, click, type, and download files that become artifacts. Browser traffic goes through the same egress policy as everything else.

isolation you can check

A node declares a runtime profile and refuses to start unless its backends can meet it. conformance --profile reports every check as pass, fail or unavailable, never healthy by omission.

How it differs from a sandbox API

  • A session is a log, not a socket. Output is kept with sequence numbers; clients replay from where they were.
  • A workspace is a value. Snapshot, move, sleep and wake, with every grant bound to a generation.
  • The workspace is trusted with nothing. Secrets, policy and lifecycle live in the node and the control plane.
  • Lifecycle belongs to the control plane. Leases and idle policy are durable timers, not a setTimeout in your worker.
  • Everything is an event, committed in the same transaction as the state it describes.
  • Nothing is hosted. The protocol is public; replace the reference implementation if you can do better.

Quick start

# build, then run a control plane and one node in one process
make build
./remount standalone --data ./data &
export REMOUNT_SERVER=http://127.0.0.1:7443

WS=$(./remount ws create --name hello)
./remount exec $WS -- sh -c 'echo hello from $(hostname)'
./remount sh $WS                 # interactive shell, real pty
./remount fs write $WS notes.md < README.md

# start something long, ^C, come back later
./remount attach $WS <session-id> --from 0
