a durable computer for AI agents

A workspace an agent can keep: a filesystem and the processes in it, on a machine you control. Snapshot it, move it to a GPU box, put it to sleep, reattach to a command that is still running, and call APIs with keys the workspace never sees. One static Go binary, one wire protocol, self-hosted, Apache-2.0.

install

go install remount.dev/remount/cmd/remount@main
# or, once a release is tagged:
curl -fsSL https://get.remount.dev/install.sh | sh

quick start (no credentials)

# control plane and one node, in one process
remount standalone --data ./data &
export REMOUNT_SERVER=http://127.0.0.1:7443

WS=$(remount ws create --name hello)
remount exec $WS -- sh -c 'echo hello from $(hostname)'
remount sh $WS                        # interactive shell, real pty
remount fs write $WS notes.md < README.md

# start something long, hit ^C, come back later
remount exec $WS -- sh -c 'for i in $(seq 1 100); do echo line $i; sleep 1; done'
remount attach $WS <session-id> --from 0

with an API key the workspace never sees

export OPENAI_API_KEY=sk-...
remount run opencode --dir . --model openai/gpt-4o-mini -- 'add a README'

# inside the workspace the variable holds a placeholder; the node's broker
# substitutes the real key only for api.openai.com and records every use
remount events --ws $WS | grep cred.used

what you can do with it

  • Reattach and never lose output. Run a coding agent for hours, close the laptop, attach, read what you missed. The session lives on the node; a dropped range is an explicit gap.
  • Move a workspace mid-task. ws move snapshots the filesystem and a node in the zone you asked for restores it. Files and policy follow; a stale client cannot act on the old placement.
  • Hand out keys the agent never sees. The workspace holds a placeholder; the broker substitutes only for allowed hosts, audits every use, and a revocation reaches a live workspace within one renewal.
  • Let background work outlive the turn. A lease keeps a workspace awake until a deadline stored in the control plane, survives your own service crashing, then sleeps the workspace instead of billing you forever.
  • Drive a browser inside the workspace. Navigate, screenshot, click, type, and download files that become artifacts, under the same egress policy as everything else.
  • Check isolation instead of trusting it. A node declares a runtime profile and refuses to start unless its backends can meet it; conformance --profile reports every check as pass, fail or unavailable.

how it differs from a sandbox API

  • A session is a log, not a socket. Output is kept with sequence numbers; clients replay from where they were.
  • A workspace is a value. Snapshot, move, sleep and wake, with every grant bound to a generation.
  • The workspace is trusted with nothing. Secrets, policy and lifecycle live in the node and the control plane.
  • Lifecycle belongs to the control plane. Leases and idle policy are durable timers, not a setTimeout in your worker.
  • Everything is an event, committed in the same transaction as the state it describes.
  • Nothing is hosted. The protocol is public; replace the reference implementation if you can do better.

how it fits together

  ┌────────────┐   outbound    ┌──────────────┐   outbound   ┌────────────┐

  │    up      │   wss:443     │  event log   │   wss:443    │    up      │
  └────────────┘               │  policy      │              └────────────┘
